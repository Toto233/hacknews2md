## 现在的处理方式

| 情况 | 动作 | 发布条件 |
| --- | --- | --- |
| 浏览器呈现明确403／拒绝访问／验证页 | 跳过截图及后续重试；自动记录日期、run_id、故事ID、精确URL和原因；续跑复用 | 可以省略该截图；正文、来源、审稿、关键词和摘要门禁仍须通过 |
| 只有HTTP客户端返回403，浏览器正文正常 | 按实际浏览器页面处理 | 保存有效截图 |
| 超时、空白或未分类失败 | 保留重试；仍失败时集中报告受影响条目 | 未解决时须取得用户对具体省略项的决定 |
| 错误图片已有有效的同一原文截图 | 规范命令恢复，清除旧省略记录，保留历史文件并重渲染 | 无须重复询问同一来源的恢复 |
| 需要换成替代来源页面 | 提供确切页面及来源关系供用户接受 | 仍需用户接受替代来源 |

正文提取已按DOM顺序保留全部文本节点，包括链接、加粗、代码标签后的文字，排除script/style。微信单篇草稿读回明确指定UTF-8。每日仍先逐条核对内容，再汇总排序和生成封面，发布后执行一次简短结果检查；已成功的草稿通过收据续跑，不因截图恢复再上传一份。

操作命令由[发布技能](../skills/publish-hacknews-codex/SKILL.md)和[恢复指南](../skills/publish-hacknews-codex/references/recovery.md)维护；旧规则的部分取代关系见[决策记录](DECISIONS.md)。

## 验证与适用范围

188项离线测试全部通过，覆盖错误页识别及误判反例、保存失败、精确省略范围、续跑不再尝试、同源恢复、替代来源权限、正文门禁仍有效、真实HTML内联文字和UTF-8响应字节。浏览器、HTTP、LLM和微信传输使用mock，数据写临时目录；规范命令的帮助页及变更空白检查通过。测试仅出现已有PyPDF2和lxml弃用提示。

识别器保守处理：正文提及403、验证码或页脚reCAPTCHA不会据此省略；未能自动判断的疑似错误图片仍需查看，超时和未分类截图失败保留重试。没有新增站点黑名单，没有重写历史内容或重新上传草稿。减少重试和重复确认的机制已验证，实际耗时与模型用量仍需以后运行观察。
